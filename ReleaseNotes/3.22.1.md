# Workflow Core 3.22.1

* Fixed [#1462](https://github.com/danielgerlag/workflow-core/issues/1462): events with no matching subscription were re-scheduled on every poll interval and never marked processed (regression in 3.22.0). Affected providers that support scheduled commands (Entity Framework providers, MongoDB, Azure Table Storage).
* `RunnablePoller` now checks the greylist before scheduling an event, for all providers.
* New option `WorkflowOptions.UseUnmatchedEventRetention(TimeSpan)` (default 5 minutes). Unmatched events are marked processed once older than this window; `TimeSpan.Zero` restores the pre-3.22.0 behaviour.
